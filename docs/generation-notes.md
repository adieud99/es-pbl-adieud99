# 데이터 생성 기록

## 1. 기본 설정

| 항목 | 값 |
|---|---|
| index | `flights` |
| 문서 수 | 10,000 |
| seed | 20260901 |
| 업무 ID field | `trip_id` |
| ID 형식 | `TRIP-00001` ~ `TRIP-10000` |
| 생성 스크립트 | `data/flights-create.py` |
| 출력 | `data/flights-10000.json`, `data/flights-10000.ndjson` |

생성기는 Python 표준 라이브러리만 사용한다. `random.seed(SEED)`를 스크립트 시작에서 한 번
호출하므로, 같은 코드와 같은 seed로 실행하면 항상 같은 데이터가 나온다.

## 2. 후보와 범위

| field | 생성 방식 | 후보 / 범위 |
|---|---|---|
| `trip_id` | 순번 | `TRIP-` + 5자리 0채움 |
| `dep_airport` | 고정값 | ICN |
| `arr_airport` | 균등 선택 | NRT(도쿄), KIX(오사카), TPE(타이베이), HKG(홍콩), BKK(방콕), SIN(싱가포르) |
| `airline` | 균등 선택 | 대한항공, 아시아나항공, 제주항공, 진에어, 티웨이항공 |
| `is_direct` | 가중 선택 | true 70 / false 30 |
| `route_desc` | 조합 | `인천 {도착 도시} 왕복 {직항\|경유}` |
| `seat_class` | 가중 선택 | economy 70 / business 20 / first 10 |
| `out_dep_time` | 균등 선택 | 2026-09-01 ~ 2026-09-30 23:59:59 (초 단위) |
| `stay_nights` | 균등 선택 | 1 ~ 10 |
| `total_price` | 균등 선택 | 300,000 ~ 1,200,000 |
| `tags` | 비복원 표본 | 특가, 수하물포함, 변경가능, 할인, 추천 중 1~2개 |

`dep_airport`를 ICN 하나로 고정한 이유는 이 PBL이 인천 출발 왕복만 다루기 때문이다.
출발지와 도착지를 모두 자유 선택으로 두면 출발과 도착이 같은 문서가 생긴다.

`route_desc`는 별도로 뽑지 않고 `arr_airport`와 `is_direct`에서 조립한다. 따로 생성하면
"직항"이라고 적힌 문서의 `is_direct`가 false가 되는 모순이 생긴다. 도착 도시명을 한글로
넣는 이유는 사용자가 "도쿄 직항"처럼 한글 단어로 검색하기 때문이다.

|---|---|---:|---:|---:|
| `total_price` | 300,000 ~ 1,200,000 | 300,029 | 1,199,769 | 750,878 |

750,000에 가까운 것으로 균등 분포임을 확인할 수 있다.

## 4. 질문별 포함·제외·경계

기준 질문은 "도쿄행 왕복 직항 이코노미 중 총액 50만원 이하를 싼 순으로"다.

| 조건 | 판정 근거 |
|---|---|
| 포함 | `arr_airport`=NRT, `is_direct`=true, `seat_class`=economy, `total_price`≤500000을 모두 만족 |
| 제외 | 네 조건 중 하나라도 어긋나면 결과에서 빠진다. 경유편은 가격이 범위 안이어도 제외된다 |
| 경계 | `total_price`가 정확히 500,000인 문서는 "이하"이므로 포함된다 |

## 5. 0건 조건

결과가 0건이어야 정상인 조건은 **단일 field의 생성 범위 밖**으로 잡았다.

| 조건 | 근거 | 실제 결과 |
|---|---|---|
| `total_price` > 2,000,000 | 생성 범위 상한이 1,200,000 | `count: 0` |
| `stay_nights` >= 30 | 생성 범위 상한이 10 | `count: 0` |

처음에는 "퍼스트클래스 총액 50만원 이하"를 0건 조건으로 잡았으나, 생성 스크립트가
`total_price`를 `seat_class`와 무관하게 뽑기 때문에 실제로는 213건이 나온다. 값이 서로
연동되는 조건 대신 한 field의 범위만으로 판정되는 조건으로 바꾸었다.

0건은 검색이 실패한 것이 아니라 조건을 만족하는 문서가 없다는 뜻이다.

## 6. 이 데이터의 한계

- **운임이 노선·좌석등급과 무관하다.** 실제 항공권은 거리와 좌석등급에 따라 운임이 달라지지만
  이 데이터는 세 값을 독립적으로 뽑는다. 싱가포르행 이코노미가 도쿄행 퍼스트보다 비쌀 수 있다.
  등급별·노선별 가격 차이는 이 데이터로 검증하지 않는다.
- **오는 편 출발 일시를 저장하지 않는다.** 오는 편 날짜는 `out_dep_time`에 `stay_nights`를
  더한 값이므로 계산할 수 있다. 별도 field로 두면 두 값이 어긋날 수 있어 저장하지 않는다.
- **개인정보를 생성하지 않는다.** 승객 이름, 여권번호, 예약번호, 연락처, 결제 수단, 실제
  예약 이력은 만들지 않는다. 항공사·공항·운임은 모두 합성값이다.

## 7. 재현 방법

```bash
cd data
python3 flights-create.py
```

같은 결과를 얻으려면 스크립트, seed, 후보 목록이 모두 같아야 한다. 후보를 하나라도 바꾸면
난수 소비 순서가 달라져 이후 모든 값이 바뀐다.
