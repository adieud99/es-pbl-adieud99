# 데이터 모델 초안

## 1. 문서 단위

- 검색 결과 한 건은 무엇인가: 왕복 항공권 1건 (가는 편과 오는 편이 짝지어진 조합)
- 이 문서 한 건이 사용자에게 보여 주는 정보는 무엇인가: 항공사, 출발·도착 공항, 가는 편 출발 일시, 오는 편 출발 일시, 체류일수, 좌석등급, 왕복 총액, 직항 여부

## 2. 대표 문서 예시

내 주제의 문서 한 건을 JSON으로 작성합니다. 실제 개인정보는 넣지 않습니다.

```json
{
  "trip_id": "TRIP-00001",
  "airline": "대한항공",
  "route_desc": "인천 도쿄 왕복 직항 3박",
  "dep_airport": "ICN",
  "arr_airport": "NRT",
  "out_flight_no": "KE1201",
  "out_dep_time": "2026-09-12T09:10:00",
  "in_flight_no": "KE1202",
  "in_dep_time": "2026-09-15T19:40:00",
  "stay_nights": 3,
  "seat_class": "economy",
  "total_price": 428000,
  "is_direct": true
}
```

## 3. 핵심 field와 역할

Day 1에는 field의 검색 역할과 ES type 후보를 초안으로 적습니다. Day 2에 mapping과 함께 확정합니다.

| field | 예시 값 | 검색에서 맡는 역할 | ES type 후보 | 선택 이유 |
|---|---|---|---|---|
| `route_desc` | 인천 도쿄 왕복 직항 3박 | 전문 검색 | `text` | 사용자가 도시명과 직항 여부를 단어로 입력하므로 문장을 쪼개 검색해야 한다. |
| `airline` | 대한항공 | 전문 검색 / 집계 | `text` + `keyword` | 문장으로 검색하지만 Dashboard에서는 항공사별로 정확히 묶어 세어야 한다. |
| `dep_airport` | ICN | 정확 조건 | `keyword` | 공항 코드는 쪼개면 의미가 없고 값 전체가 일치해야 한다. |
| `seat_class` | economy | 정확 조건 / 집계 | `keyword` | 좌석등급을 정확히 고르고 등급별로 묶어 비교한다. |
| `out_dep_time` | 2026-09-12T09:10 | 범위 / 정렬 | `date` | 출발 주간과 오전·오후 시간대를 범위로 좁힌다. |
| `stay_nights` | 3 | 범위 / 집계 | `integer` | 며칠 일정으로 다녀올지 조건을 걸고 체류일수별로 총액을 비교한다. |
| `total_price` | 428000 | 범위 / 정렬 / 집계 | `integer` | 예산 상한을 걸고 싼 순으로 정렬하며 평균을 낸다. |
| `is_direct` | true | 정확 조건 | `boolean` | 양편 모두 직항인 조합만 남기는 참·거짓 조건이다. |

## 4. 검색 질문과 field 연결

| 검색 질문 | 사용할 field | 확인할 역할 |
|---|---|---|
| "도쿄 직항" 항공권 검색 | `route_desc`, `airline` | 전문 검색 |
| 총액 50만원 이하 왕복 직항 이코노미를 싼 순으로 | `is_direct`, `seat_class`, `total_price` | 정확 조건 / 범위 / 정렬 |
| 노선별·체류일수별 평균 총액 확인 | `dep_airport`, `arr_airport`, `stay_nights`, `total_price` | 집계 |

## 5. 제외할 데이터

- 수집하거나 저장하지 않을 개인정보: 승객 이름, 여권번호, 예약번호, 연락처, 결제 수단, 실제 예약 이력
- 제외 이유: 이 PBL은 항공권 자체를 검색하는 과제이며 개인정보가 필요하지 않다. 항공사·공항·편명·운임은 모두 합성값을 사용한다.
