# 4교시 연습 — 가격 분포·재고 비율·등록 시점

공통 문제는 `products`, 개인 문제는 `flights`. 실행 2026-09-03.

## (공통·필수) 문제 1 — 50,000원 단위 가격 분포

`Create custom ranges`로 구간을 직접 넣었다. `Decrease granularity`를 반복하면 경계가
어디에 잡히는지 알 수 없어서 쓰지 않았다.

### 결과 입력

- 실제 입력한 구간:

| 구간 | 문서 수 |
|---|---:|
| 0 이상 50,000 미만 | **3,621** |
| 50,000 이상 100,000 미만 | 2,289 |
| 100,000 이상 150,000 미만 | 1,359 |
| 150,000 이상 200,000 미만 | 1,264 |
| 200,000 이상 | 1,467 |
| 합계 | **10,000** |

- 구간 사이 빈틈·중복 확인 방법: **합계가 전체와 같은지로 확인했다.** 3,621 + 2,289 +
  1,359 + 1,264 + 1,467 = 10,000으로 Metric과 정확히 맞는다. 빈틈이 있으면 합이 모자라고,
  겹치면 합이 넘친다. 둘 다 아니므로 구간이 전체를 빠짐없이 한 번씩 덮었다.

  구간 경계는 `이상 ~ 미만`으로 잡아야 겹치지 않는다. 100,000을 두 구간에 다 넣으면
  그 값이 두 번 세어진다.

- 가장 많은 가격 구간: **0 이상 50,000 미만**
- 해당 구간 실제 문서 수: **3,621건** (전체의 36.2%)
- 제목: `가격 구간별 상품 수`
- 캡처 파일: `picture/products.png`

저가 쪽으로 몰린 오른쪽 꼬리 분포다. 5만원 미만이 3,621건인데 20만원 이상은 1,467건이다.
`price >= 200000`으로 KQL을 걸어도 1,467건이 나와 구간 값과 맞는다(1교시 문제 5).

## (공통·필수) 문제 2 — 재고 상태 Donut과 기준값 검증

차트 유형은 `Pie`를 고르고 `Style → Appearance → Donut hole → Medium`으로 바꿨다.
차트 목록에 Donut이라는 항목이 따로 없다.

### 결과 입력

- true 실제 값: **8,469** (84.7%)
- false 실제 값: **1,531** (15.3%)
- 합계: **10,000**
- 전체와 일치하는가: 일치한다. Metric 10,000과 같다.
- 비율 또는 값 표시 방식: 비율(%)로 표시했다. 두 조각뿐이라 값보다 비율이 읽기 쉽다.
- 제목: `재고 상태 비율`
- 한 조각만 보일 때 먼저 확인할 조건: 순서대로 본다.
  1. **KQL** — `in_stock : true` 같은 조건이 남아 있으면 한 값만 남는다.
  2. **filter pill** — 같은 조건이 filter로 걸려 있을 수 있다.
  3. **Control 선택값**
  4. **Lens의 Number of values** — 1로 줄어 있으면 상위 1개만 나온다. boolean이라 2면 충분하다.
  5. 시간 범위 — 좁으면 한쪽 값만 있는 구간이 잡힐 수 있다.

  이 순서인 이유는 위쪽일수록 화면에서 눈에 안 띄면서 영향이 크기 때문이다. Lens 설정은
  패널을 열어야 보이니 마지막에 본다.

- 캡처 파일: `picture/products.png`

## (공통·필수) 문제 3 — 월별 상품 등록 Line과 잘못된 해석 수정

`created_at` Date histogram에 `Minimum interval`을 `1M`으로 입력했다. 자동으로 두면
시간 범위에 따라 주/일 단위로 바뀌어 월별 비교가 안 된다.

### 결과 입력

- 선택한 interval: `1M` (월)
- 보이는 월 구간: 2025-08 ~ 2026-08, 13개 구간

| 월 | 등록 수 |
|---|---:|
| 2025-08 | **131** |
| 2025-09 | 817 |
| 2025-10 | 808 |
| 2025-11 | 818 |
| 2025-12 | 872 |
| 2026-01 | 860 |
| 2026-02 | 793 |
| 2026-03 | 831 |
| 2026-04 | 812 |
| 2026-05 | 853 |
| 2026-06 | 842 |
| 2026-07 | 818 |
| 2026-08 | **745** |

  가운데 11개월이 793~872로 거의 평평하다. 양 끝만 낮은데, `created_at` 실제 범위가
  2025-08-27 ~ 2026-08-26이라 **첫 달과 마지막 달이 잘린 것**이다. 2025년 8월은 5일치,
  2026년 8월은 26일치만 들어 있다.

- 실제 패널 제목: `월별 상품 등록 수`
- 수정한 설명 문장:

> ~~월별 판매량이 증가하거나 감소하는 모습을 보여 준다.~~
>
> **월별로 상품이 카탈로그에 새로 등록된 건수를 보여 준다. 2025년 9월부터 2026년 7월까지
> 매달 793~872건으로 거의 일정하다. 양 끝 달이 낮은 것은 등록이 줄어서가 아니라 데이터
> 수집 기간이 그 달 중간에서 시작하고 끝나기 때문이다.**

- `created_at`의 실제 의미: **상품이 시스템에 등록된 시각.** 누가 샀는지, 언제 팔렸는지와
  아무 관계가 없다. 등록만 하고 한 번도 안 팔린 상품도 이 그래프에 들어간다.
- 판매 추이를 알려면 추가로 필요한 사건/field:

| 필요한 것 | 형태 | 왜 |
|---|---|---|
| 주문 사건 | 별도 index (문서 1건 = 주문 1건) | 상품 문서로는 "몇 번 팔렸나"를 표현할 수 없다 |
| `ordered_at` | date | 판매 시점 |
| `quantity` | integer | 몇 개 팔렸나 |
| `order_status` | keyword | 취소·환불 제외 |

  상품 index에 판매 field를 억지로 넣으면 안 된다. 한 상품이 여러 번 팔리므로 문서 하나에
  담기지 않는다. 사건(주문)은 사건대로 별도 index가 맞다.

- 캡처 파일: `picture/products.png`

## (개인·필수) 문제 4 — 분포·비율·시간 중 하나 선택

- 선택 유형: **분포**
- 사용자 질문: "우리 항공권 상품이 어느 가격대에 몰려 있나?"
- field와 mapping type: `total_price` / integer
- 그룹/구간/시간 단위: 30만원 단위 custom ranges 3구간
- 차트: Bar (histogram)
- 완료 기준: 구간 합이 10,000과 같아야 한다.
- 실제 결과:

| 구간 | 건수 |
|---|---:|
| 300,000~599,999 | 3,287 |
| 600,000~899,999 | 3,390 |
| 900,000~1,199,999 | 3,323 |
| 합계 | **10,000** |

  min 300,029 / max 1,199,769 / avg 750,878. 세 구간이 3,287 / 3,390 / 3,323으로 거의
  균등하다.

- 해석 시 주의할 한계: **이 분포는 시장 가격 구조가 아니라 데이터 생성 방식의 결과다.**
  운임을 30만~120만 균등 난수로 만들었기 때문에 평평하게 나온다. 실제 항공권이라면 저가가
  많고 고가가 적은 한쪽으로 치우친 분포가 나와야 정상이다. `products`의 가격 분포가
  5만원 미만 3,621건 / 20만원 이상 1,467건으로 치우친 것과 비교하면 차이가 뚜렷하다.

  그리고 좌석등급과 가격이 무관하게 생성돼서, 이 분포를 등급별로 쪼개도 세 등급이 거의
  같은 모양이 나온다. "비즈니스가 비싸다"를 이 차트로 보여줄 수 없다.

## (선택 도전) 문제 5 — 가격 구간 대안 비교

`products`에서 field와 Count는 유지하고 구간만 바꿨다.

| 비교 | 50,000원 단위 (5구간) | 대안: 10만 단위 (3구간) |
|---|---|---|
| 막대 수 | 5개 | 3개 |
| 읽기 쉬움 | 라벨이 5개라 조금 빽빽하지만 읽을 만하다 | 한눈에 들어온다 |
| 판단에 유용함 | 5만 미만 3,621이 최다인 게 드러난다. 10~15만(1,359)과 15~20만(1,264)이 비슷하다는 것도 보인다 | 10만 미만 5,910 / 10~20만 2,623 / 20만 이상 1,467. 큰 흐름만 보이고 중간 구간 차이가 뭉개진다 |

- 최종 선택과 이유: **50,000원 단위.** 이 데이터에서 가격이 몰려 있는 곳이 5만원 미만인데,
  10만 단위로 끊으면 그게 "10만 미만 5,910"에 묻힌다. 5만 단위여야 저가 쏠림의 크기가
  보인다.

  구간을 정할 때 기준은 "몇 개가 보기 좋은가"가 아니라 "답하려는 질문이 그 구간에서
  드러나는가"다. 질문이 "고가 상품이 몇 개인가"였다면 3구간으로도 충분했을 것이다.

## 교시 완료 신호

**GREEN.** price Bar(구간 합 10,000 검증), stock Donut(8,469 + 1,531 = 10,000),
created_at Line(1M interval, 잘못된 해석 문장 수정), 개인 분포 유형 선택을 모두 마쳤다.
`created_at`을 판매 추이로 읽지 않는다는 것을 문장으로 고쳐 적었다.
