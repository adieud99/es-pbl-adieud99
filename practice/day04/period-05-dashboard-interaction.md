## (공통·필수) 문제 1 — 6패널을 읽는 순서로 배치

### 배치 기록

- Dashboard 제목: `수업` (저장하지 않아 현재 Kibana에 남아 있지 않다. 문제 4 참고)
- 첫 행 패널: `전체 상품 수` Metric, `카테고리별 상품 수` Bar
- 둘째 행 패널: `브랜드별 상품 수와 평균 가격` Table, `재고 상태 비율` Donut,
  `가격 구간별 상품 수` Bar
- 셋째 행 패널: `월별 상품 등록 수` Line
- 가장 크게 배치한 패널과 이유: 브랜드 Table. 열이 3개(브랜드·상품 수·평균 가격)이고
  행이 40개라 좁으면 브랜드 이름이 잘리고 숫자가 줄바꿈된다. 표는 값을 정확히 읽으라고
  만든 패널이라 잘리면 존재 이유가 없어진다.
- 크기를 늘려 해결한 가독성 문제: **브랜드 이름 열이 잘리는 문제.** 처음 캡처에서 왼쪽이
  잘려 숫자만 보이고 어느 브랜드인지 알 수 없었다. 패널 폭을 늘려 이름·상품 수·평균 가격이
  한 줄에 다 들어오게 했다.
- 제목이 비어 있던 패널과 수정 결과: Metric 패널이 기본값 `Count of records`로 남아
  있었다. `전체 상품 수`로 바꿨다. 차트 이름이 아니라 그 패널이 답하는 내용을 제목으로
  써야 한다.
- 캡처 파일: `evidence/day-04/common-dashboard.png`

## (진단·필수) 문제 3 — Control·Filter·KQL을 구분하고 초기화

`products` Data View가 없어서(문제 4 참고) 이 문제는 **개인 `flights` Dashboard**로 했다.
셋 다 실제로 적용하고 매번 화면을 캡처했다. 시간 범위는
`Jan 1, 2026 @ 09:00 → Jan 1, 2027 @ 08:59`로 고정했다.

| 방식 | 입력한 조건 | 적용 전 값 | 적용 후 값 | 해제 방법 | 해제 후 값 |
|---|---|---:|---:|---|---:|
| Control | `airline.keyword` = 진에어 | 10,000 | **2,063** | 드롭다운 `Any` | 10,000 |
| Filter | `seat_class : business` | 10,000 | **2,004** | filter pill `×` | 10,000 |
| KQL | `total_price >= 600000` | 10,000 | **6,713** | 입력줄 비우고 Enter | 10,000 |

세 값 모두 `_count`와 대조했고 전부 일치한다.

```http
GET /flights/_count { "query": { "term":  { "airline.keyword": "진에어" } } }    → 2,063
GET /flights/_count { "query": { "term":  { "seat_class": "business" } } }      → 2,004
GET /flights/_count { "query": { "range": { "total_price": { "gte": 600000 } } } } → 6,713
```

Filter를 걸었을 때 함께 변한 패널도 확인했다(`p05-q03-filter.png`).

| 패널 | 전체 | business만 |
|---|---|---|
| Metric | 10,000 | 2,004 |
| 항공사 Donut | 진에어 20.63% 1위 | **제주항공 21.11% 1위** |
| 도착지 Bar 순서 | SIN, NRT, BKK, HKG, TPE, KIX | **SIN, BKK, NRT, HKG, TPE, KIX** |
| 히트맵 범례 | 303~331.8 | **56~66.4** |

  도넛 조각 비율을 집계와 대조했다. 제주항공 423/2,004 = 21.11%, 아시아나 418 = 20.86%,
  진에어 394 = 19.66%, 대한항공 360 = 17.96%로 화면과 소수점까지 같다. 전체에서 5위였던
  제주항공이 business에서는 1위가 된다.

- 세 방식의 사용자가 느끼는 차이:

| | 만든 사람 | 쓰는 사람 | 해제 | 화면에서 보이는 위치 |
|---|---|---|---|---|
| **Control** | 제작자가 미리 배치 | 드롭다운에서 고름. 값 목록이 보임 | `Any`로 되돌림 | 패널 위 드롭다운 |
| **Filter** | 보는 사람이 추가 | 알약으로 조건이 보임. 클릭해 수정·비활성화 | `×` | KQL 줄 아래 알약 |
| **KQL** | 보는 사람이 타이핑 | 문법을 알아야 함 | 지우고 Enter | 상단 입력줄 |

  Control은 **반복해서 바꿀 조건**, Filter는 **한 번 걸고 유지하거나 클릭으로 만드는 조건**,
  KQL은 **복잡한 조합**에 쓴다. 셋 다 결과는 같은 식으로 좁혀지지만 값이 이상할 때
  **찾아봐야 할 곳이 다르다.**

- **여기서 실제로 사고가 났다.** 세 조건을 차례로 적용하는데 Filter 단계에서 Metric이
  2,004가 아니라 **1,365**로 나왔다. business가 2,004인 걸 알고 있었기 때문에 바로 이상한
  걸 알아챘다.

  원인은 **앞 단계의 KQL이 안 지워진 채로 남아 있던 것**이었다. `total_price >= 600000`이
  걸린 상태에서 `seat_class: business` filter를 추가했으니 두 조건의 AND가 된 것이다.
  검증해보니 business 2,004 × 가격조건 비율 0.67 ≈ 1,343으로 1,365와 맞는다.

  화면상 KQL 입력줄과 filter 알약은 **다른 줄에 있어서 하나만 보고 있으면 다른 하나를
  놓친다.** 문제지가 "한 방식을 확인한 뒤 반드시 지우고 다음으로 이동합니다"라고 못박은
  이유를 몸으로 확인했다. 조건을 지우고 다시 하니 정확히 2,004가 나왔다.

- 모든 조건 제거 후 전체값: **10,000** (`p05-q03-baseline.png`)
- `Filter for value` 문구가 없을 때 확인한 filter pill과 변한 패널: 차트 조각을 클릭했을 때
  툴팁이 안 떠도 클릭하면 상단에 알약이 생긴다. 알약이 생겼는지로 판단하면 되고, 생겼다면
  그 조건에 걸린 모든 패널이 함께 변한다.
- 캡처 파일:

| 파일 | 상태 |
|---|---|
| `picture/p05-q03-baseline.png` | 조건 없음, 10,000 |
| `picture/p05-q03-kql.png` | KQL `total_price >= 600000`, 6,713 |
| `picture/p05-q03-filter.png` | Filter `seat_class: business`, 2,004 |

## (공통·필수) 문제 4 — 목요일 종료용 저장·재열기

### 저장·복구 기록

- 실제 저장 이름: **저장되지 않았다.**
- 저장 시각: 없음
- 다시 열기 성공 여부: **실패**
- 패널 수 / Control 초기값 / KQL·filter 상태 / Metric 값: 확인 불가

Saved Objects API로 확인한 결과다.

```http
GET /api/saved_objects/_find?type=dashboard   → 총 1개 (fligths dashboards)
GET /api/saved_objects/_find?type=index-pattern → 총 1개 (flights*)
GET /api/saved_objects/_find?type=lens        → 총 0개
```

- 남아 있는 Dashboard: `fligths dashboards` (개인 flights) 하나뿐
- 남아 있는 Data View: `flights*` 하나뿐
- **`products` Data View도, 공통 Dashboard도, 저장된 Lens도 없다.**

공통 실습은 편집 모드에서 화면만 만들고 저장 없이 끝난 것으로 보인다. 캡처
(`evidence/day-04/common-dashboard.png`)는 그때 찍은 화면이라 값이 남아 있지만, 그 화면을
다시 열어 확인할 방법이 없다. 그래서 그 캡처의 997건이 어떤 조건에서 나온 값인지
지금은 확인할 수 없다.

- 다시 열었을 때 달라진 항목: 해당 없음

**다음부터 할 것.** Dashboard는 패널을 다 만든 직후에 저장한다. 저장하지 않으면 편집
상태는 브라우저를 닫는 순간 사라지고, 캡처만 남아 나중에 검증이 불가능해진다.
저장할 때 `Store time with dashboard`를 켜야 시간 범위까지 복구된다. 이번에 개인
Dashboard는 저장했기 때문에 URL(`/app/dashboards#/view/2ee36d5d-...`)로 다시 열어
재현할 수 있었다.

- 전체 화면 캡처: `evidence/day-04/common-dashboard.png` (당시 화면),
  `picture/p05-q03-baseline.png` (개인 Dashboard 재열기 성공)

## (선택 도전) 문제 5 — 30초 사용성 테스트

실제 테스트는 하지 못했다. 대신 스스로 두 행동을 해보고 걸린 지점을 적는다.

- 상대가 처음 본 패널: 왼쪽 위 Metric. 숫자가 제일 크고 위에 있어서 눈이 먼저 간다.
  의도한 대로다.
- 조건 선택 성공 여부: 성공. Options list가 드롭다운이라 값 목록이 보여서 바로 고를 수 있다.
- 복구 성공 여부: 성공. 다만 `Any`가 "전체"라는 뜻인지 바로 와닿지 않는다.
- 상대가 멈출 만한 지점:
  1. **`Any`의 의미.** 조건을 지우려는 사람이 `×`를 찾다가 못 찾는다. Control에는 지우는
     버튼이 아니라 `Any`로 되돌리는 방식이다.
  2. **브랜드 Table 40행.** 스크롤이 생겨서 아래에 뭐가 더 있는지 모른 채 지나친다.
  3. **막대 높이가 다 같은 category Bar.** 차트가 고장 난 줄 안다. 실제로는 8개가 전부
     1,250건이라 그런 건데, 설명이 없으면 오해한다.
- 수정할 제목·배치·Control label: Control label을 `카테고리 선택`에서
  **`카테고리 (전체 보려면 Any)`** 로 바꾸면 1번이 해결된다. category Bar는 제목을
  `카테고리별 상품 수 (8종 균등)`로 바꿔 오해를 줄일 수 있다.

## 교시 완료 신호

**YELLOW.** 배치·Control·세 조건 전후 비교는 캡처와 집계 대조까지 마쳤다. 다만 두 가지가
걸린다. 공통 Dashboard를 **저장하지 않아 재열기를 못 했고**(문제 4), `products` 건수가
교재 기준 20,000이 아니라 10,000이다(1교시).

이번 교시에서 제일 크게 배운 것은 문제 3의 사고다. KQL을 안 지운 채 filter를 추가해
1,365라는 엉뚱한 값을 봤는데, 미리 집계로 2,004를 알고 있었기 때문에 바로 잡아냈다.
**화면 숫자를 검증할 기준값을 갖고 있어야 조건이 겹친 걸 알아챌 수 있다.**
